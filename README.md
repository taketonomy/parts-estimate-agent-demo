# parts-estimate-agent-demo

Fictional-data prototype: a parts-estimate agent that retrieves similar parts and past estimates (RAG-style) and drafts an estimate with cited grounds. Offline, Python standard library only, with a leave-one-out backtest.

> **All data in this repository is fictional.** Parts, prices, estimates and dates were generated by `scripts/generate_data.py` from a simple internal pricing model. The "drafting" step is retrieval-based (weighted median / percentiles over retrieved records). **No external LLM, API, or network access is used.**

## What it does

1. **Retrieve** – the free-text query is compared against each part's name + category + material + spec in `data/parts_master.csv` using TF-IDF cosine similarity over word tokens and character 3/4-grams. The top-k parts (default 5) and their past estimates in `data/past_estimates.csv` are retrieved (at most 8 estimates).
2. **Draft** – each retrieved estimate gets a weight `similarity^3` (multiplied by a quantity-closeness factor if `--qty` is given). The draft contains:
   - suggested unit price = weighted median of retrieved unit prices
   - price range = weighted 25th–75th percentile of retrieved unit prices
   - suggested lead time = weighted median of retrieved lead times
3. **Cite** – every figure is an actual retrieved value and is printed with the `estimate_id`, `part_id` and price/lead time it came from, followed by the full table of retrieved estimates and parts. No figure is produced without a source; if nothing is retrieved, no draft is printed (exit code 1).

## Files

| Path | Contents |
|---|---|
| `data/parts_master.csv` | 40 fictional parts (`part_id`, `name`, `category`, `material`, `spec`, `typical_unit_price`) |
| `data/past_estimates.csv` | 60 fictional past estimates (`estimate_id`, `part_id`, `quantity`, `unit_price`, `lead_time_days`, `date`) |
| `scripts/generate_data.py` | Deterministic generator for both CSVs (documents the pricing model) |
| `agent.py` | Retrieval + draft CLI |
| `backtest.py` | Leave-one-out backtest |
| `tests/` | `unittest` suite |

Pricing model used to generate the data (JPY, typical price at qty 100): `family_base x material_factor x (size / ref_size)^0.8 x (1 + 0.12 x extra_ops) x finish_factor`. Past estimates add a quantity factor (x1.15 at qty 10 to x0.92 at qty 500), a 2%/year drift and +-4% noise, so similar parts have similar prices.

## How to run

Requires Python 3.8+ and nothing else.

```bash
python3 agent.py "L bracket SUS304 t2.0 60x60" --qty 100
python3 backtest.py            # add --details for per-case results
python3 -m unittest discover
python3 scripts/generate_data.py   # optional: regenerates identical CSVs
```

### Sample output (`backtest.py`)

```
$ python3 backtest.py
Leave-one-out (hide one estimate):
  cases:                         60 (drafted: 60)
  median absolute % error:       10.1%
  hit rate within +/-20%:        65.0%
Stricter: hide all estimates of the same part (new-part scenario):
  cases:                         60 (drafted: 60)
  median absolute % error:       28.8%
  hit rate within +/-20%:        41.7%
```

The backtest hides one estimate at a time, uses that part's name + spec as the query and the hidden quantity as `--qty`, and compares the suggested unit price with the hidden actual price. It has no randomness, so results are identical on every run. The stricter variant also hides the other estimates of the same part, which simulates quoting a part never quoted before.

## Scope

### Verified
- `python3 -m unittest discover` passes (11 tests). They check that:
  - the data loads and every estimate references a master part
  - four known queries return the expected nearest part, and same-family parts rank first
  - every draft figure for every part cites at least one retrieved `estimate_id` whose value equals the figure
  - the printed draft has a citation on each figure line
  - hidden estimates are never used
  - the backtest is deterministic and reaches >= 50% hit rate within +-20%
- Backtest on the fictional data: leave-one-out gives 60 cases, median APE 10.1% and a 65.0% hit rate within +-20%. The stricter new-part scenario gives median APE 28.8% and a 41.7% hit rate. These figures only describe this synthetic dataset.
- `scripts/generate_data.py` reproduces the committed CSVs exactly.

### Requirements (for a production version)
- Real historical estimates and part master data, with cleaning, unit/currency normalisation and versioning.
- Better retrieval: synonyms and domain vocabulary (e.g. "stainless" -> SUS304 is not matched today), structured attribute matching (material, dimensions, tolerances, finish), and/or embeddings.
- Price adjustment for quantity, material-cost changes and date drift (today quantity only re-weights retrieved records; figures are never adjusted).
- Backtest on real data with a time-based split, plus accuracy targets agreed with the people who use the estimates.
- Human review and approval before any estimate is sent, with an audit log of the cited sources.
- Access control and data protection for pricing data.

### Unimplemented
- Real LLM text generation (the draft is retrieval-based statistics, not an external LLM)
- Real company data or ERP / procurement system integration
- Authentication / authorisation
- Web UI
